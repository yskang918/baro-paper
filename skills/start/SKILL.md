# 바로논문

연구자의 시간을 아끼되, 결정은 연구자가 한다.

## 구조 한눈에

| 구간 | 하는 일 | 사용자가 보는 것 |
|---|---|---|
| **A. 자동 구간** (연구 세팅까지) | 실제 조건 묻기 → 중복 거름망 → 문헌 조사 → 연구 세팅 → 판단 | 처음 질문 한 번, 끝에 **판단 카드 한 장** |
| **B. 연구 동반** (진행하기로 한 뒤) | 계획서, 장별 집필, 자료 분석, 심사, 학교 양식 hwpx | **대화창**에서 보고 정하기, 문서는 필요할 때만 |

아이디어가 없거나 넓으면 A 앞에 **브레인스토밍**(ideate 스킬, 아이디어 카드 한 장)을 먼저 한다.

## 지킬 원칙

- **가정하지 않는다.** 대상·기간·학급 수·협력 교사·기기·대학원·마감 같은 조건을 모르면 채워 넣지 않고 묻는다. 끝내 모르는 것은 `미정`으로 두고 판단 카드의 "결정 전에 할 일"에 올린다. 사용자가 말하지 않은 수업 장면·학생 반응·현장 계기를 지어 쓰지 않는다. (가정 표는 사용자가 "자동 시험"이라고 밝힌 경우에만 쓴다.)
- **지어내지 않는다.** 설문 응답·면담·데이터·통계값·논문을 만들지 않는다. 인용 문헌은 모두 `verify_reference`(baro-scholar)로 확인하고, 확인 못 한 것은 `[미확인]`으로 표시한다.
- 사용자에게 보이는 글은 한국어, 쉬운 말. 확인한 것과 추정을 나눈다.
- **결정할 때만 보여 준다.** 사람이 정하는 곳은 다섯 군데다: ① 주제 고르기 ② 진행 여부 ③ RQ 확정 ④ 장별 개요 승인 ⑤ 제출 전 최종 확인. 그 밖의 단계는 대화창에 "무엇을 했다" 한 줄만 남기고 계속한다.
- 보여 줄 때는 결론부터, 근거 3개 안팎, 자세한 것은 접거나 `자료/`에, 숫자·문장마다 출처, 확인 못 한 것은 따로, 끝은 "다음에 할 일".
- 질문은 한 번에 3개까지(AskUserQuestion). 내가 정할 수 있는 일은 묻지 않는다.
- 작업 폴더 `연구/<짧은 주제 이름>/`. 이미 있는 파일은 덮어쓰기 전에 확인한다. 단계가 끝나면 `진행상태.md`(지금 단계, 정한 것, 미정, 다음 할 일)를 갱신한다. "이어서 하자"면 이 파일부터 읽는다.

## 폴더

```
연구/<주제>/
  판단카드.html  card.json  진행상태.md
  자료/                      ← A 구간의 자세한 파일(카드에서 펼쳐 봄)
    00_조건.md               (사용자가 답한 실제 조건, 미정 목록)
    01_중복확인.md
    01_문헌/  문헌목록.md · 문헌종합.md · insane-research 결과
    02_RQ대응표.md           (이후 모든 단계의 기준)
    02_연구세팅.md           (도구·일정·자료 수집·분석·윤리)
    03_판단보고서.md
  계획서/ 원고/ 분석/ 심사/ 제출/   ← B 구간(필요할 때 생김)
  문체프로필.md               (사용자가 자료를 줬을 때만)
```

# A. 자동 구간

## A0. 세팅 확인

```bash
python "${CLAUDE_PLUGIN_ROOT}/skills/setup/scripts/setup.py" check
```
(`python`이 없으면 `python3`.) `install-python`·`install-plugins`가 필요하면 **setup 스킬**부터. **OpenAlex 키가 없으면** 문헌 조사 전에 한 번 묻는다(받기 / 이미 있음 / 이번엔 없이 — setup 스킬 3번, 동의 없이 이메일을 보내지 않음, "없이"를 고르면 `진행상태.md`에 적어 다시 묻지 않음). KCI 키·한글 보안 모듈은 한 줄로 알린다.

## A1. 실제 조건 묻기 → `자료/00_조건.md`

아이디어를 한 문장으로 다시 써서 보여 주고, **모르는 것만** 묻는다(3개씩, 많아야 두 번).
- 대상: 학교급·학년·학급 수·인원, 연구자의 역할(담임·전담·외부)
- 여건: 기간(언제부터 몇 주), 수업 시간 확보, 기기, 협력 교사, 기존 기록·자료
- 목적: 학위논문·학술지·계획서, 대학원·제출처, 마감, 선호하는 연구 방법(모르면 추천)
- 현장 계기(있으면 사용자 말 그대로 적음)
답을 그대로 적고, 답하지 않은 항목은 `미정`으로 적는다. **이 단계 뒤에는 판단 카드까지 묻지 않고 진행한다.**

## A2. 중복 거름망 (5분) → `자료/01_중복확인.md`

넓은 조사 전에 싸게 확인한다. **lit-scout 에이전트**(가벼운 모델)에게 맡긴다: 핵심 검색어 3~5개(한국어·영어)로 `kci_search`(키 있으면) · `openalex_search` · `crossref_search`를 돌려 **가장 비슷한 연구 5편**을 찾아 대상·방법·변인을 적게 한다.
- **같거나 아주 비슷한 연구**(대상·방법·핵심 변인이 거의 같음)가 있으면 여기서 멈추고 보여 준 뒤 묻는다: 차이를 두고 계속 / 방향 바꾸기 / 그만. 이것이 가장 큰 시간·비용 절약이다.
- 비슷한 연구가 있지만 차이가 분명하면 한 줄로 알리고 계속한다.

## A3. 문헌 조사 → `자료/01_문헌/`

1. 검색은 **lit-scout 에이전트**에게 키워드별로 나눠 동시에 맡긴다(국내·국외, 최근 5~10년 + 고전). 에이전트는 찾은 문헌을 `verify_reference`(DOI가 있으면 꼭 `doi`)로 확인해 `문헌목록.md` 표 형식으로 돌려준다: 저자·연도·제목·학술지·DOI/KCI ID·찾은 DB·확인 여부·핵심 한 줄.
2. **넓은 조사**(정책·현황·이론): `insane-research`가 있으면 `insane-research:insane-research-main`을 **보통 깊이로 한 번** 부른다. 질문은 A1 조건으로 구체적으로. 낸 학술 출처는 다시 확인해 목록에 합친다. 없으면 직접 웹 검색.
3. OpenAlex "하루 한도" 오류가 나면 멈추지 말고 `crossref_search`로 대신하고 키 등록을 한 줄 권한다.
4. `문헌종합.md`(이것은 직접 쓴다): 핵심 이론(정의), 선행연구 흐름(국내·국외), 측정 도구 후보(출처·문항 수·신뢰도·한국어판 여부), 연구 빈틈, 가장 비슷한 연구 3편과 차이.

## A4. 연구 세팅 → `자료/02_RQ대응표.md`, `자료/02_연구세팅.md`

### RQ 대응표 (이후 모든 단계의 기준)
RQ는 2~4개, **RQ1, RQ2… 번호 고정**. RQ마다:
```
## RQ1. <한 문장 — 계획서·원고·분석·심사에서 글자 그대로 쓴다>
- 유형: 기술 / 관계 / 효과 / 경험 / 개발
- 하위 질문: RQ1-1 … (있을 때만)
- 가설: H1 … (양적·효과 RQ일 때만)
- 조작적 정의: 무엇을 어떻게 재는가
- 근거: 문헌목록 번호·빈틈
```
| RQ | 자료 | 도구(출처·문항 수) | 수집 시기 | 분석 방법 | 결과가 들어갈 곳 | 답할 수 있나 |
|---|---|---|---|---|---|---|

규칙: 자료로 답할 수 있어야 함("아니오"면 고치거나 뺌), 한 RQ에 한 질문, 유형과 분석이 맞을 것, RQ를 고치면 대응표부터 고치고 다른 파일에 반영. 조건이 `미정`이라 문장을 확정할 수 없으면 그 부분을 `[미정: 학년]`처럼 남긴다.

### 연구 세팅 (구체적으로, A1 조건과 문헌에서만)
- **설계와 대상**: 연구 설계, 집단 구성, 표집, 인원(검정력 계산은 statsmodels 등으로 실제 계산하고 가정한 값을 밝힘)
- **측정 도구**: RQ별 도구 후보 — 출처·문항 수·신뢰도·한국어판 여부·사용 허락 필요 여부. 새로 만들어야 하면 그렇게 적는다(문항을 지어내 완성품처럼 쓰지 않음)
- **진행 일정표**: 주별(사전 준비·기준선·처치·검사·면담·정리), A1의 기간에 맞춤
- **자료 수집 계획**: 언제·무엇을·어떻게·누가, 개인정보 처리
- **분석 계획**: RQ별 분석, 가정 확인, 대안(비모수 등), 효과크기
- **윤리·승인 점검표**: IRB 경로, 학교장 승인, 보호자·학생 동의, 불이익 없음, 연구자=담임일 때 대책, 자료 보관·파기
- **미정 목록**: 세팅을 확정하려면 사용자가 정해야 할 것

## A5. 판단 → `자료/03_판단보고서.md` + 판단 카드

1. **idea-review 스킬**로 보고서를 만든다.
2. RQ 문장이 파일끼리 같은지 검사한다:
```bash
python "${CLAUDE_PLUGIN_ROOT}/skills/start/scripts/rq_check.py" "연구/<주제>/자료/02_RQ대응표.md" "연구/<주제>/자료/03_판단보고서.md" "연구/<주제>/자료/02_연구세팅.md"
```
3. `card.json`을 쓰고(`${CLAUDE_PLUGIN_ROOT}/skills/start/card_schema.md`, 숫자·인용·RQ 문장은 `자료/`에서 그대로) 카드를 만들어 연다:
```bash
python "${CLAUDE_PLUGIN_ROOT}/skills/start/scripts/make_card.py" "연구/<주제>/card.json" -o "연구/<주제>/판단카드.html" --open
```
4. 대화창에는 5줄 이내(결론, RQ 핵심, 가장 큰 걸림돌, 미정·결정 전 할 일, 카드 경로) + AskUserQuestion: **진행 / 고쳐서 다시 / 보류**.
   - 고쳐서 다시: 문헌은 다시 찾지 않고 A4~A5만 다시 한다(이전 판은 `자료/_이전/`).
   - 진행: RQ를 한 번 더 보여 주고 확정받는다(결정 ③). 확정되면 B 구간으로.

# B. 연구 동반 (진행하기로 한 뒤, 사용자가 부를 때)

자동으로 이어 달리지 않는다. 사용자가 "계획서 쓰자", "Ⅱ장 같이 쓰자", "사전 검사 자료 들어왔어", "학교 양식으로 만들어 줘"처럼 말하면 그 일을 한다. 대화창에서 보여 주고 정한다(무엇을 했는지 3~5줄 + 핵심 표 하나 + 정할 것). md는 각 폴더에 두되 읽으라고 하지 않는다. 한글 파일(hwpx)·PDF는 사용자가 원할 때(지도교수께 드릴 때, 제출할 때)만 **thesis-format 스킬**로 만든다. 언제나 `자료/02_RQ대응표.md`를 기준으로 하고, 끝나면 `진행상태.md`를 갱신한다.

- **계획서** (`계획서/`): RQ 문장을 그대로, 방법은 RQ 순서로. 학교·기관 양식을 주면 그 구성으로.
- **집필** (`원고/`): 먼저 장별 개요를 보여 주고 승인(결정 ④). 결과 장은 RQ마다 한 절. **thesis-writing-ko** 규칙, `문체프로필.md`가 있으면 그 문체(학교 지침이 가장 우선). `academic-research-skills:academic-paper`를 쓸 수 있다("한국어 학위논문, thesis-writing-ko 규칙, Markdown"을 함께 지시). 실제 자료가 없는 결과는 쓰지 않고 `[자료 수집 후 작성]`.
- **분석** (`분석/`): **data-analysis 스킬**, 받은 실제 자료만, RQ 순서·대응표의 방법대로, 파일 이름에 RQ 번호. 방법을 바꾸면 이유를 적고 대응표를 고친다.
- **심사** (`심사/`): `academic-research-skills:academic-paper-reviewer`가 있으면 그것으로, 없으면 idea-review 반론 방식 + thesis-writing-ko 점검표. `rq_check.py`로 원고 전체의 RQ 일관성을 검사한다. 고칠 목록에서 사용자가 고른 것만 고친다.
- **제출 양식** (`제출/`): **thesis-format 스킬**. 그때 받은 양식을 정확히 읽어 조판·대조(결정 ⑤).
- **문체 학습**: 사용자가 자료를 주면 **style-learning 스킬**.

## 끝낼 때
무엇을 했는지, 생긴 파일, 사용자가 정할 것·미정·확인하지 못한 것을 짧게.
