# 바로논문: 아이디어에서 제출 양식까지

연구자의 시간을 아끼되, 결정은 연구자가 한다. 단계마다 결과 파일을 남기고, 결정이 필요한 곳에서는 멈추고 묻는다.

## 0. 세팅 확인 (처음 한 번, 이후에는 빠르게)

```bash
python "${CLAUDE_PLUGIN_ROOT}/skills/setup/scripts/setup.py" check
```
(`python`이 없으면 `python3`.) `todo`에 `install-python`이나 `install-plugins`가 있으면 **setup 스킬**의 절차를 먼저 따른다. 선택 항목(KCI 키, 한글 보안 모듈)은 한 줄로 알리고 넘어간다.

## 지킬 원칙

- **지어내지 않는다.** 설문 응답·면담 내용·데이터·통계값·논문은 만들어 내지 않는다. 인용하는 문헌은 모두 `verify_reference`(baro-scholar MCP)로 확인하고, 확인 못 한 것은 `[미확인]`으로 표시한다.
- 사용자에게 보이는 글은 한국어로 쓴다. 쉬운 말로 쓰고, 확인한 것과 추정을 나눠 쓴다.
- 질문은 한 번에 3개까지만 한다(AskUserQuestion). 내가 정할 수 있는 일은 묻지 않는다.
- 결과는 작업 폴더 `연구/<짧은 주제 이름>/` 에 쌓는다. 파일이 이미 있으면 덮어쓰기 전에 보여 주고 확인한다.
- 매 단계가 끝나면 `진행상태.md`(지금 단계, 결정한 것, 다음 할 일)를 갱신한다. "이어서 하자"면 이 파일부터 읽는다.

## 폴더 구조

```
연구/<주제>/
  진행상태.md
  00_아이디어.md
  01_문헌/  문헌목록.md (검색어·DB·확인 여부) · 문헌종합.md · insane-research 결과
  02_연구설계.md
  03_판단보고서.md
  04_연구계획서.md
  05_원고/  1장.md … (thesis-format 스킬의 원고 규칙대로)
  06_분석/  분석.py · 결과표 · 그림
  07_심사/  심사보고서 · 수정 기록
  08_제출/  양식 분석 · map.json · 결과.hwpx · 대조 보고서 · 쪽 그림
  문체프로필.md (사용자가 자료를 줬을 때만)
```

## 1단계. 아이디어 다듬기 → `00_아이디어.md`

사용자가 준 아이디어를 한 문장으로 다시 써서 보여 준다. 다음 중 모르는 것만 묻는다(최대 3개씩).
- 대상(학교급·학년·인원)과 연구자가 그 대상에 접근할 수 있는지(담임·전담·외부)
- 현장에서 본 문제나 계기
- 쓸 수 있는 기간과 자료(수업 시간, 기기, 기존 기록, 설문 가능 여부)
- 원하는 결과물(학위논문·학술지·연구계획서)과 제출처, 마감
- 선호하는 연구 방법(양적·질적·혼합·개발연구·실행연구) — 모르면 4단계 판단 때 추천

## 2단계. 문헌 조사 → `01_문헌/`

1. 검색어를 한국어·영어 동의어로 만든다(예: 인지 오프로딩 / cognitive offloading / 인지적 위임 / 외부 기억 / AI 의존).
2. **학술 DB 검색(baro-scholar MCP)**
   - 국내: `kci_search`(키가 있으면). 키가 없으면 `openalex_search`에 한국어 검색어를 넣는다.
   - 국외: `openalex_search` (최근 5~10년 + 많이 인용된 고전을 따로).
   - 각 문헌을 `문헌목록.md` 표에 적는다: 저자·연도·제목·학술지·DOI/KCI ID·찾은 DB·확인 여부·핵심 내용 한 줄·우리 연구와의 관계.
3. **넓은 조사**: `insane-research` 플러그인이 있으면 Skill 도구로 `insane-research:insane-research-main`을 불러 정책·현황·이론까지 넓게 조사한다. 질문은 1단계 내용으로 구체적으로 만든다(대상·맥락·알고 싶은 것). 없으면 직접 웹 검색으로 대신한다.
4. insane-research가 낸 학술 출처도 `verify_reference`로 다시 확인해 `문헌목록.md`에 합친다.
5. `문헌종합.md`: 핵심 이론(정의 포함), 선행연구 흐름(국내·국외 나눠), 측정 도구 후보(출처·문항 수·신뢰도), **아직 안 된 것(연구 빈틈)**, 우리 연구와 가장 비슷한 연구 3편과 차이.

## 3단계. 연구 설계 → `02_연구설계.md`

연구의 필요성(문헌 근거를 달아서), 연구문제(2~4개, 답할 수 있는 형태), 이론적 틀, 연구 방법(설계·대상·표집·도구·절차·자료 분석), 일정표, 윤리(아동 대상이면 IRB·보호자 동의·개인정보·수업 중 불이익 없음), 예상 결과의 형태(무엇을 보고하게 될지), 한계. 연구문제마다 "어떤 자료로 어떻게 답하는지"를 표로 잇는다.

## 4단계. 할지 말지 판단 → `03_판단보고서.md`

**idea-review 스킬**로 보고서를 만든다. 결론을 보여 준 뒤 AskUserQuestion으로 묻는다: 진행 / 고쳐서 다시 판단 / 보류. 진행이 아니면 여기서 멈추고 고칠 점을 정리한다.

## 5단계. 연구계획서 → `04_연구계획서.md`

2~4단계 내용을 계획서 형식으로 쓴다(서론·이론적 배경·연구 방법·일정·참고문헌). 학교·기관 양식을 주면 그 장 구성을 따르고, hwpx가 필요하면 **thesis-format 스킬**로 만든다.

## 6단계. 집필 → `05_원고/`

- 먼저 장별 개요를 보여 주고 승인을 받은 뒤 쓴다.
- **thesis-writing-ko 스킬**의 규칙을 따른다. `문체프로필.md`가 있으면 그 규칙이 우선이고, 학교 지침이 있으면 지침이 가장 우선이다.
- `academic-research-skills` 플러그인이 있으면 장 집필·인용 점검에 활용할 수 있다(예: `academic-research-skills:academic-paper`). 이때 "한국어 학위논문, thesis-writing-ko 규칙, 원고는 05_원고에 Markdown"을 함께 지시한다. 없으면 직접 쓴다.
- 결과 장은 실제 데이터가 있어야 쓴다. 데이터가 없으면 자리만 두고 `[자료 수집 후 작성]`으로 표시한다.

## 7단계. 데이터 분석·시각화 → `06_분석/`

**data-analysis 스킬**. 사용자가 준 실제 자료만 분석한다.

## 8단계. 심사·수정 → `07_심사/`

`academic-research-skills:academic-paper-reviewer`가 있으면 그것으로, 없으면 idea-review의 반론 방식과 thesis-writing-ko 점검표로 스스로 심사한다. 고칠 목록을 보여 주고, 사용자가 고른 것만 고친다.

## 9단계. 제출 양식 → `08_제출/`

**thesis-format 스킬**. 사용자가 그때 준 양식(견본 hwpx/hwp, 지침 문서)을 정확히 읽어 그대로 조판하고, 대조 보고서를 남긴다.

## 문체 학습 (언제든)

사용자가 자기 원고나 대화 기록을 주면 **style-learning 스킬**로 `문체프로필.md`를 만든다. 자료를 안 주면 만들지 않는다.

## 끝낼 때

무엇을 했는지, 어떤 파일이 생겼는지, 사용자가 결정할 것과 확인하지 못한 것을 짧게 정리한다.
